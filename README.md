# learning-studio
プログラミング学習システム

## ローカルで起動

このアプリは静的ファイルのみで動作し、GitHub Pagesへそのまま公開できます。リポジトリのルートで次を実行してください（Python 3）。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Firebase SDKの取得と、既存Firebaseプロジェクトへの接続が必要です。`config.js` とFirestoreセキュリティルールは今回の改修では変更していません。

## Web開発レベル1

- 左側のPDF教材は「表示倍率」で50％・75％・90％・100％（幅に合わせる）・125％・150％・200％を選べます。100％未満では教材を中央に配置します。拡大後は教材枠内を縦横にスクロールできます。「原本PDFを開く・印刷」も利用できます。
- ページ送り（前のページ・ページ選択・次へ）は画面上部に固定され、教材や問題のスクロール中も操作できます。バーの高さに合わせて教材とエディターの領域を確保し、スマートフォンの2段表示や画面の回転にも追従します。教材と問題はそれぞれの枠内でスクロールできます。
- 12ページの切り替えで右側のミッション・確認問題が連動します。入力中のHTML・CSS・JavaScriptとページ別回答は保持します。
- エディターはフローティング表示です。見出しをドラッグして移動、右下の ↘ をドラッグしてサイズ変更、「最小化」で隠し、「エディターを開く」で復元できます。移動とサイズ変更はそれぞれの操作部にフォーカスして矢印キーでも行えます。Escで最小化、「位置を戻す」で画面内に配置し直せます。
- スマートフォンは「教材」「実習・問題」を切り替え、エディターを必要なときだけ開けます。タッチでの移動・サイズ変更にも対応します。
- 生徒のコードは「学習内容を保存」、ページ別回答は「このページを保存」で既存の `web_workspaces` ドキュメントへmerge保存します。自動保存と端末への一時保存も継続します。ローカル下書きがある場合はクラウド読み込みによる上書きを避け、端末の入力を優先します。ブラウザのデータ削除や他の端末へはローカル下書きが引き継がれないため、Firebaseの保存状態を確認してください。

テスト手順と検証範囲は [tests/README.md](tests/README.md) を参照してください。

## 12ページの順次学習と再開

画面上部に「HTML入門 レベル1｜全12ページ」、現在ページ、全体進捗を表示します。「ページ一覧」またはページ選択で、学習済み・学習中・未学習・ロック中を確認できます。右側の大見出しは「このページの学習・進捗チェック」、ページ固有のタイトルは「学習テーマ」として表示します。

- 初回は第1ページから開始します。第1ページは教材の使い方とHTMLの基礎を読む導入ページです。確認問題や必須ミッションはなく、「使い方を確認して次へ」または固定ヘッダーの「次へ」で読了を記録して第2ページへ進めます。第2〜10ページは、必須の選択問題・操作確認・コード課題を完了し「回答とコードをチェック」を押すと、次のページを解放します。記述式の応用問題は任意です。学習済みページは復習できます。
- 第11ページの「最終確認テスト」は第1〜10ページの必須学習完了後に解放します。選択8問・記述2問の全問回答が提出条件です。正誤にかかわらず、提出後に第12ページを解放します。従来のレッスン全体の最終提出フォームも、第11ページの提出後に利用できます。
- 第12ページでは操作確認と「今日、できるようになったこと」の記述が必須です。残りの振り返り記述は任意です。
- 先生は全ページをプレビューできます。教材画面の「先生用：生徒の学習進度を調整」で生徒を選び、進度を読み込んでから学習済み扱いの範囲（0〜12ページ）を保存できます。範囲を戻した場合も回答・コードは残り、生徒の次回ログイン・教材再表示時に新しい解放状態を適用します。第11ページ以降を学習済み扱いにするとテスト提出済み扱いになります。権限エラー時は保存できなかった旨を表示します。

既存の `web_workspaces/{uid}__{lessonId}` の `pageWork` 内に `_learning`（バージョン1）を追加し、学習位置・ページ完了・訪問状態・テスト提出状態を保存します。既存の `p01`〜`p12` の回答・判定とコードは保持し、旧形式のチェック済み必須学習から進度を復元します。旧形式の最終テストは、第1〜10ページの必須学習完了と全10問の回答・チェック済み記録がそろっていれば、提出済みとして復元します。それ以外も回答は保持し、新しい提出操作で続けられます。ローカルで未保存の回答はクラウド履歴と併合します。履歴の取得前・取得失敗時には未知のクラウド進度を自動保存で上書きしません。先生の調整は独立したスナップショットとして保持し、古い生徒端末の保存によって消えないようにします。

クラウド保存が成功した状態なら、別の端末や再ログイン後も学習位置・解放状態を復元できます。通信エラー時は端末への一時保存とクラウド保存を区別して表示します。先生の進度調整には既存のFirestoreルールによる書き込み権限が必要です。今回ルールは変更していません。ページロックは教室内の学習順序を案内するブラウザ側の機能であり、サーバー側の試験不正対策を追加するものではありません。

## 一体型の固定ヘッダー

共通の `#lsHeader` の上段（`#243B70`）にサービス名・教室名・ログイン中の利用者・ログアウトを表示します。HTML入門レベル1では、その直下の下段（`#365C96`）にページ操作・現在ページ・進捗バーを配置します。それ以外の画面とログアウト後は下段を取り除き、共通部分だけを表示します。

PCでは2段を基本とし、スマートフォンでは前後ボタンを矢印にして細い進捗バーを配置します（ボタンのアクセシブル名は維持）。ログアウトは高さ44px以上、幅72px以上の独立した操作領域を確保します。長い利用者名は画面幅に合わせて省略表示し、完全な名前は要素のtitleと読み上げ用テキストに保持します。

`assets/page-navigation.js` が教材操作DOMを共通ヘッダーへ移し、`ResizeObserver` でヘッダー全体を測定します。本文の余白・PDFと問題の表示領域・フローティングエディターの移動可能範囲は、その測定値を共有します。ページ操作自体には独立した固定位置を設定しません。

## 1ページ目の教材とチェックの整合

1ページ目の「今日の目標」「道具の組み合わせ」「見出しの役割」「見本を見つける」等の旧確認問題は表示しません。教材の進め方、HTMLの導入、画面の使い方だけを案内します。原本PDFと画面用画像の「分からない言葉に印をつけよう」は「分からない言葉は先生に聞こう」に統一しています。

読了は既存の `pageWork.p01.introRead` に記録します。旧問題の `answers` / `results` はそのまま保持し、新しい意味の設問には流用しません。旧版で1ページ目の必須5項目を達成済みの記録と、既存のページ完了状態も引き継ぎます。PDFの2〜12ページおよび対応する設問は変更していません。

学習の流れは「Input（インプット）→ Output（アウトプット）→ Check（確認）→ Reflect（振り返り）」の4段階です。教材や説明から知識を取り入れ、コードを書いて使い、表示を確かめ、できたこと・できなかったことを振り返って次の学習につなげます。必要に応じて教材に戻り、コードを直して再確認します。画面とPDFの案内を統一しています。

## 教材更新とブラウザキャッシュ

CSS・アプリと依存するローカルJavaScript・PDF・ページ画像には、内容のSHA-256から生成した `?v=` を付けます。教材を更新するとURLが変わるため、以前のJavaScriptや画像が端末にキャッシュされていても、更新後のHTMLから新しいファイルを取得できます。学習位置・回答・コードのローカル保存は消しません。

アセットを変更したら、コミット前に次を実行してください。

```sh
npm run version:assets
npm test
```

`version:assets` はPDF・画像の対応表（`assets/asset-versions.js`）、ローカルモジュールのimport、`index.html`の参照を更新します。`npm run check:assets` は参照と内容の整合を確認し、`npm test`でも最初に実行します。生成結果もコミットするので、GitHub Pagesで公開するときの追加ビルドは不要です。`config.js`、Firebase SDKのURL、Firestoreルールは変更しません。

公開反映には変更ブランチのマージとGitHub Pagesの公開処理が必要です。公開後はブラウザで再読み込みしてください。教材画面を開いたままのページ送りだけでは、読み込み済みのJavaScriptは入れ替わりません。公開処理が完了する前のHTMLを取得した場合は、まだ旧表示になることがあります。

## 教材ページと進捗チェック

HTML入門の第2〜12ページは、各ページの問題・実習に必要な説明と操作手順を含む本文で表示します。ダウンロードする教材PDFにもこの本文を使用します。第1ページは引き続き導入です。教材枠の本文の下に「この教材ページで取り組むこと」を表示し、現在のページ別問題に連動します（先生が保存した教材も対象）。第11ページのテストでは、この一覧に正解・解説を表示しません。

先生がクラウド保存済みの本文は引き続き優先します。今回の既定本文を取り入れる場合は、現在のJSONをバックアップし、`assets/html-level1-workbook.json` と必要な変更を合わせて先生の編集画面から読み込み・保存してください。先生の原稿を自動上書きしません。

## 図解教材とフローティングエディター

Web開発コース①の全30教材を、完成見本→しくみの図→コードの変更箇所→実習→振り返りの5ページで表示します。ゲームの実画面30点、内容別の図解30点、コードの変更図30点を使用します。詳しい文章は折りたたみ、各ページと同じ内容のチェックを隣に表示します。図は100〜200%に拡大でき、「教材を印刷・PDF保存」で5ページの教材を出力できます。

エディターは移動・サイズ変更・最小化できるフローティング表示です。初期状態は最小化し、教材を見ながら必要なときに開きます。ページ移動や最小化でコード・実行中のゲームを作り直しません。既に登録済みの教材も、サイトの更新後にこの表示へ変わります。教材の再登録は不要で、先生の原稿・公開設定・生徒の保存コードは保持します。先生が原稿を変更した場合は標準見本の画像であることを明示します。

図解の原稿は `assets/web-course-visuals.json`、ゲームの原稿は `assets/web-course.json` です。更新時は `npm run visuals:assets` → `npm run version:assets` → `npm test` を実行します。画像は実際の初期コードからローカルのChromiumで撮影し、図と変更箇所はSVGとして生成します。外部画像サービスは使用しません。
